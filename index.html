    How it works

    Every note in the index was embedded the same way, ahead of time. Search is exact cosine similarity, which is what a flat FAISS index does. The map is a 2-D projection of the 16-number vectors. The answer is stitched only from the retrieved notes, so it cannot invent facts. In GHOST the vectors come from a real embedding model and the answer from an Ollama LLM.

    How it works
              
    GHOST (Generalized Hybrid Operating System for Thought) is my local-first personal AI OS, built with Python, FastAPI, Ollama and MCP. A request reaches the FastAPI backend; Qwen3 0.6B decides whether an MCP tool is needed; the MCP Manager runs it (filesystem, browser or tasks); relevant memories are pulled from SQLite; for document questions nomic-embed-text + FAISS return the top 3 chunks; Qwen3 8B writes the reply; messages and newly extracted memories (categorised, de-duplicated) are saved to SQLite.

    This panel is a simulation of that flow, not the real backend.
    
          
    
        
    
        
    Simulation. Runs entirely in your browser. It does not contact Ollama, SQLite or any MCP server: routing, retrieval, tool results, timings and replies are scripted to mirror how the real GHOST works.

      How it works
              
      This is one attention head running the real formula, softmax(Q·Kᵀ / √d) · V, on your sentence. Each word gets a query, a key and a value vector. In a trained LLM those come from learned weight matrices and a model has dozens of heads per layer; here the weights are hand-set so each head does one readable job (resolve pronouns, look one word back, link a verb to its subject). Words outside the small vocabulary are treated as things.
